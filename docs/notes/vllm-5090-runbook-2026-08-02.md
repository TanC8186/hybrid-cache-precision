## MVP serving 路径（无需新内核）

用 vLLM 现有 `int4_per_token_head` + 逐层保护：
```
--kv-cache-dtype int4_per_token_head \
--kv-cache-dtype-per-layer 23:float16,3:int4_per_token_head,7:int4_per_token_head,11:int4_per_token_head,15:int4_per_token_head,19:int4_per_token_head
```
即：layer23（敏感）保持 fp16，其余 int4。对比 fp16 baseline。

## 5090 上运行命令

```bash
# 环境（镜像克隆 vLLM 后打 patch）
git clone --depth 1 --filter=blob:none https://ghfast.top/https://github.com/vllm-project/vllm vendor/vllm
git apply vendor/vllm-patches/per-layer-kv-dtype.diff   # 在 vendor/vllm 内

# 构建（sm_120）
TORCH_CUDA_ARCH_LIST="12.0" uv pip install -e .

# 逐层分配
python scripts/exp/gen_allocation.py --threshold 0.15

# serving benchmark（三个分配）
python scripts/exp/vllm_serving_bench.py --allocation fp16 --num-reqs 200 --max-len 8192
python scripts/exp/vllm_serving_bench.py --allocation uniform_int4 ...
python scripts/exp/vllm_serving_bench.py --allocation results/ablations/allocation.json ...
```

## 注意事项
- Qwen3.5-2B 是 multimodal，vLLM 会加载 vision encoder；文本评测够用
- flashinfer 采样 JIT 需要 CUDA_HOME（本地 pip CUDA 问题；5090 全量 CUDA 无此问题）
- 容量卖点：量化 KV → 更多 block → 更长上下文/更大 batch（4096→16K+）
