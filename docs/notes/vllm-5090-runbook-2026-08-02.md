## ⚠️ 脚本审查结论（2026-08-03，启动服务器前必读）

上一版 `vllm_serving_bench.py` / `vllm_smoke.py` **存在 3 个必踩的坑**，已修复（commit `f544b0d`）：

1. **`--kv-dtype float16` 会崩**：Qwen3.5-2B 模型是 bf16，float16 KV cache 让 flash-attn 报
   `query and key must have the same dtype`。**非量化 baseline 一律用 `auto`**（跟随模型 bf16）。
   - 已修：`vllm_serving_bench.py` 的 `--allocation fp16` → `kv_cache_dtype="auto"`；`vllm_smoke.py` 默认 → `auto`
2. **TTFT/TPOT/KV 容量 API 全臆造**：`llm.engine`、`last_ttft`/`last_tpot`/`kv_cache_config` **不存在**。
   正确来源（已查证源码）：
   - TTFT = `RequestOutput.metrics.first_token_latency`（`vllm/v1/metrics/stats.py` RequestStateStats）
   - TPOT = `(metrics.last_token_ts − metrics.first_token_ts) / (metrics.num_generation_tokens − 1)`
   - KV 容量 = `llm.llm_engine.vllm_config.cache_config.num_gpu_blocks × block_size`（`vllm/config/vllm.py:340`）
   - **`RequestOutput.metrics` 依赖 `log_stats`**：`disable_log_stats=True` 时是 None（`outputs.py:177`）→ benchmark 不要设它
3. **MODEL 路径**：默认 `data/modelscope_cache/...` 在服务器不存在；现自动探测本地/服务器两个路径。

**技术疑点（待查）**：全局 `kv_cache_dtype=float16` 崩，但 per-layer 里 `layer23:float16` 不崩（冒烟通过）。
现象已确认、原因未解释。per-layer 保护层暂保持 `float16`（已验证），bench 前先跑 per-layer smoke 复核。

## 运行命令（5090，环境就绪后）

```bash
cd /root/autodl-tmp/MLSys_Research && source .venv/bin/activate && export VLLM_USE_FLASHINFER_SAMPLER=0

# 0. 环境自检
ls /root/autodl-tmp/caches/modelscope/models/Qwen--Qwen3.5-2B/snapshots/master/model.safetensors
python -c "import vllm; print(vllm.__version__)"

# 1. per-layer smoke（复核 float16 保护 + 机制）
python scripts/exp/vllm_smoke.py --kv-dtype int4_per_token_head \
  --kv-per-layer 23:float16,3:int4_per_token_head,7:int4_per_token_head,11:int4_per_token_head,15:int4_per_token_head,19:int4_per_token_head

# 2. serving benchmark（fp16 基线 → MVP per-layer 分配）
python scripts/exp/vllm_serving_bench.py --allocation fp16 --num-reqs 100 --max-len 4096
python scripts/exp/vllm_serving_bench.py --allocation default_alloc --num-reqs 100 --max-len 4096
python scripts/exp/vllm_serving_bench.py --allocation uniform_int4 --num-reqs 100 --max-len 4096

# 3. 生成 per-layer 分配（从敏感度，threshold 决定保护层）
python scripts/exp/gen_allocation.py --threshold 0.15
```

`vllm_serving_bench.py` 参数：`--allocation fp16|uniform_int4|default_alloc|<json路径>`、`--num-reqs`、`--max-len`、
`--max-tokens`、`--warmup-n`（默认 5）、`--seed`、`--out`（结果 json，默认 `experiments/bench_*_<ts>.json`）。
