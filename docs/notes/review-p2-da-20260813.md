## Review Body

### Strongest Counter-Argument

这篇论文的诚实披露纪律在 MLSys 投稿中罕见且值得肯定：失败的门限（Gate 4 的 183/720 越界）被保留在 abstract 里、两次 formal runs 并列报告、多重比较校正（BH-FDR/Holm/Bonferroni）执行规范、"equality does not establish equivalence" 的措辞自律，都是该领域应当学习的做法。但恰恰是这种披露纪律让拒稿叙事变得清晰：论文可验证的贡献被限定到了一个接近定义性成立的事实上。

最强的拒稿论证如下。第一，headline 的 capacity effect 是算术的必然：r_state(L)=(A·L+G_fp32)/(A·L+G_bf16) 在 G 减半时恒大于 1，因此"全部 52 对都偏向 bf16"不携带任何经验信息——它是分母单调性的推论而非发现；真正被测到的是 15.44% 的中位幅度，而该幅度由 vLLM 块粒度舍入主导（int4 2B：2064 vs 1072 tokens/block），是特定引擎实现特定形状下的产物，不是 hybrid serving 的稳健属性。第二，标题主张——两个精度维度应当"联合"分配——从未被检验：没有任何实验对照 joint 与 independent/sequential 分配，而论文自己的 stacking 证据（叠加 bf16 state 无额外 perplexity/GSM8K 代价）恰恰说明两维度近似可分，抽掉了 jointness 的必要性；论文从未正面处理这一自我矛盾。第三，唯一统计显著的质量终点是负面的：2B GSM8K 显著下降 1.0 点（p=0.025），而正向证据（RULER 全零 delta）被论文自己限定为"非等价性"，且与"该臂干预未生效"（no-op）的解释完全相容。第四，serving 层面 0/60 单元格通过 BH-FDR、四配置矩阵未过自己的 Gate 4、TTFT P95 仅 10/18 单元格复现。综合起来，论文剩下的可验证内容是：一个既有 vLLM 开关产生了预期的算术效果，并伴随一个被测出的质量代价与一个未验证的 selector——这是一份诚实的技术报告，但不是一篇有系统贡献的 MLSys 主轨论文。

### Ignored Alternative Explanations/Paths

1. **No-op 假说（RULER 臂）**：精确到 sample-level 的 30/30 全等更相容于"state-dtype 开关在该臂未改变执行计算"，而非"bf16 状态数值不敏感"。作者把"temporal attempt 精确复现"当作可靠性证据，但它证明的是测量可复现而非干预有效。若 no-op 假说成立，RULER 臂对"state-bf16 质量影响"提供的信息量为零，比"低分辨率但真实的等价观察"更糟。此解释未被论文检验（未报告质量臂 dtype 生效追踪），且与 capacity 臂的验证纪律不对称，故优于作者的"精确一致=透明但低分辨率"叙事。
2. **块粒度舍入主导幅度**：15.44% 中位增益的幅度由 vLLM 分配器的 block 重划分（2064→1072 tokens/block）决定。替代叙事是"这是 vLLM 在特定形状下的实现产物"：在 FlashInfer 式分页 state、不同 block size 或不同 padding 布局下，幅度会变，headline 数字的跨引擎稳健性未被评估。作者承认舍入是残差来源，但将其呈现为"模型的精化"而非"headline 幅度的归因威胁"——后者是更诚实的解释框架。
3. **可分性叙事（作者自己的数据支持）**：stacking 无额外代价 ⇒ 两维度独立 ⇒ "joint budget" 约化为"两个独立开关 + 共享内存约束"。更简单路径（静态规则：state 恒 bf16，KV dtype 按质量下限选）未被测试，可能达到 selector 的一切效果且零工程复杂度。若此路径成立，"joint precision budgeting" 的贡献降级为"报告了一个既有 flag 的效果"。
4. **质量代价的机制性叙事**：2B GSM8K 的 1.0 点回归被 MDE 框架修辞性降权；替代叙事是"该开关对 2B 数学推理有真实质量代价，且 2B/9B 差异未解释"。作者未提供任何机制性探测（为何 9B 无回归、哪些层/哪类 token 受影响），operational rule 也未按模型规模条件化。

### Missing Stakeholder Perspectives

1. **延迟 SLO 敏感的运营者**：TTFT P95 复现失败（10/18 单元格、最大 75.39% 差异）意味着 capacity 杠杆的延迟影响不可预测；论文对此类部署没有任何采用指南（selector 的 TTFT 约束本身依赖不可复现的测量）。
2. **TP/多 GPU 用户**：TP 分析是"expectation, not a measurement"；9B 在多卡上的真实比率未知，而多卡是 9B 级模型的常见部署形态。
3. **2B 数学推理任务的部署者**：论文自己的数据（−1.0 点显著回归）对他们的影响被 operational rule 忽略——rule 未按模型规模条件化，相当于向恰好遭受显著质量代价的用户群体无条件推荐该开关。
4. **引擎开发者（vLLM/FlashInfer 分配器维护者）**：残差由 block 舍入主导这一发现暗示分配器设计（padding、block size、state 分页方式）才是真正的杠杆，但论文未向该受众提炼可操作结论，把一个引擎级的改进机会呈现为模型级的精度开关故事。
5. **质量优先部署（fixed memory → maximize quality 方向）**：论文只探索了"固定质量下界 → 最大化容量"；未探索用 bf16 state 省下的字节回购 KV 精度（如 int4→fp16 KV 的质量增益），而后者是更保守、风险更低的部署姿态，可能是部分运营者的真实偏好。

### Unexamined Premise

1. **Frame-lock: jointness 被当作默认正确的研究框架而非待检验假设**。标题即锁定"Joint Precision Budgeting"，全文未设置任何检验"独立/顺序分配是否足够"的实验；而论文自己的可分性证据（stacking 无交互）恰恰对该前提提出质疑。作者从未正面处理这一张力——若 premise 不成立，贡献 (b) 与论文标题同时失效。
2. **目标函数锁定：capacity 是稀缺品**。全文默认"内存受限下最大化并发/容量、质量只需下界"是部署目标；"固定内存、最大化质量"的反向分配从未被当作备选目标检验，尽管省下的 state 字节（2B 每序列 9.32 MiB）可以实质性地回购 KV 精度（int4→fp16 的质量提升空间显然大于零，而论文恰好测得 int4 KV 有 2.72 点 GSM8K 显著回归——即回购的收益是已知非零的）。

### Observations (Non-Defects)

1. **披露纪律示范级**：失败的 Gate 4 保留在 abstract、两次 formal runs 并列报告（并明确标注"run-stability evidence, not an independent sample"）、多重比较校正执行规范、保留负面结果而非转化为 performance headline——这是同类投稿中罕见的做法，值得领域效仿。
2. **内部数字一致性经抽查全部成立**：capacity 比率（+37.6/40.6/11.5/14.0%）、657/904 并发序列与 247 slots、18.63/24.84 MiB（层数×1,085,440 B 换算吻合）、537+183=720、所有 CI 以点估计为中心对称、abstract 与正文数字一致。
3. **Seed 分辨率图（Fig. 8）与 paired 分析设计**是透明报告的典范，把"汇总 CI 背后的 seed 间变异"直接呈现给读者。
4. **结论边界自律**（"It is not evidence that the selected allocation dominates baselines across models or workloads"、"This equality does not establish equivalence"）为 M1/M5 的批评预留了准确的空间——问题不在诚实，而在诚实之后的剩余贡献量级。
